# Порівняння трьох кадрів: Real-ESRGAN і Gemini

Це окремий локальний інструмент. Він не змінює фотографії, сторінки чи розгортання сайту.

Для однакового порівняння використовуються три **невеликі вихідні кадри**, вирізані з таблиць галереї за її фактичними координатами:

- Вітальня / Minimalism / Economy — рами вікон, меблі, тонкі лінії.
- Кухня / Industrial / Budget — фасади, фурнітура, стики й тверді поверхні.
- Спальня / Scandinavian / Premium — постіль, штори й фактури текстилю.

Для кожного кадру зберігаються оригінальний PNG, контрольне масштабування Lanczos, Real-ESRGAN та результат Gemini. За замовчуванням фінальні порівнювані JPEG — **1440 × 1080**. Режим `--resolution 4k` створює **4096 × 3072** зі збереженням композиції 4:3. AI-результати також зберігаються в їхньому нативному розмірі до фінального зменшення.

## 1. Підготувати окрему копію та локальний модуль

Якщо ви вже створили окрему копію для експорту галереї на Mac:

```bash
cd "$HOME/Downloads/briller-gallery-export-source" &&
git pull --ff-only origin preview &&
npm run gallery:compare:setup
```

Для нової окремої копії:

```bash
git clone --single-branch --branch preview https://github.com/brillerhouse/website.git "$HOME/Downloads/briller-upscale-test" &&
cd "$HOME/Downloads/briller-upscale-test" &&
npm ci &&
npm run gallery:compare:setup
```

Потрібні Node.js 20+ і звичайний npm. Додатковий модуль ONNX Runtime встановлюється лише в `tools/upscale/node_modules`, окремо від залежностей сайту. CPU підтримується на macOS 11+ Intel/Apple Silicon, Windows і Linux; CUDA чи Python для запуску не потрібні. Інсталятор автоматично обирає сумісну версію runtime для macOS 11–13.3, тому старіший Intel Mac не мусить завантажувати бібліотеку, що потребує macOS 13.4. Використання CPU може зайняти кілька хвилин; прогрес показується в терміналі. На слабшому комп’ютері можна вказати `--threads 2`.

## 2. Вказати Gemini API key у поточному терміналі

Потрібен ключ Gemini Developer API з Google AI Studio та доступ/квота для моделі генерації зображень із виходом 2K. Вебпідписка на застосунок Gemini сама по собі не надає API-квоту. Скрипт використовує `gemini-3-pro-image-preview` за замовчуванням; доступність моделі перевіряється перед генерацією. Якщо ця модель недоступна у вашому акаунті, задайте актуальну image-модель з підтримкою `imageSize: 2K/4K` через `GEMINI_IMAGE_MODEL` або `--model`.

У Bash або Zsh на Mac введіть ключ приховано:

```bash
printf 'Gemini API key: '; read -r -s GEMINI_API_KEY; printf '\n'; export GEMINI_API_KEY
```

У Windows PowerShell:

```powershell
$secret = Read-Host 'Gemini API key' -AsSecureString; $env:GEMINI_API_KEY = [System.Net.NetworkCredential]::new('', $secret).Password
```

Після виконання команди вставте ключ і натисніть Enter. Символи ключа не відображаються.

Ключ залишається у змінній середовища цього термінала та передається Google лише в HTTPS-заголовку `x-goog-api-key`. Не додавайте його в код, Git, JSON-звіт або чат. Скрипт не зберігає ключ і не передає його в URL. Реальні запити Gemini можуть бути платними за тарифом вашого API-акаунта.

## 3. Запустити обидва методи

```bash
npm run gallery:compare -- --run
```

У Downloads з’явиться папка `briller-upscale-comparison-<дата>` з `comparison.html` і `comparison.json`. Відкрийте HTML подвійним кліком: локальний вебсервер не потрібен. У звіті є вибір лівого/правого варіантів, повзунок порівняння, масштаб 100–300%, окремі файли й статуси помилок.

За нормального запуску це **три запити генерації Gemini**, по одному для кожної кімнати. Запит перевірки доступності моделі не генерує зображень. Автоматичних повторних запитів генерації немає; після timeout або помилки статус залишається помилкою.

## Інші режими

Лише локальний Real-ESRGAN, без ключа й запитів Google:

```bash
npm run gallery:compare -- --run --methods realesrgan
```

Лише Gemini, без додаткового локального AI-модуля:

```bash
npm run gallery:compare -- --run --methods gemini
```

Тільки вирізати оригінали та підготувати контрольні зображення, **без AI-обробки**:

```bash
npm run gallery:compare
```

Задати зручну папку (вона має бути новою):

```bash
npm run gallery:compare -- --run --output "$HOME/Downloads/briller-upscale-test-results"
```

Якщо запуск перервався або ви спочатку виконали лише один метод, продовжуйте в тій самій папці:

```bash
npm run gallery:compare -- --run --resume --output "$HOME/Downloads/briller-upscale-test-results"
```

Готові результати з перевіреними контрольними сумами пропускаються. Якщо Gemini вже повернув результат, повторний платний виклик не робиться. Для невдалого/перерваного запиту явний повтор може спричинити ще одне списання; попередній timeout не доводить, що Google не обробив запит. Якщо змінилися модель, промпт або оригінали, потрібна нова папка — результати різних налаштувань не змішуються.

Власні три кадри можна вказати через `--ids id1,id2,id3`; вони мають бути з трьох різних типів приміщень і мати пропорції 4:3.

Після роботи можна прибрати ключ зі змінних поточного термінала: `unset GEMINI_API_KEY` (Bash/Zsh) або `Remove-Item Env:GEMINI_API_KEY` (PowerShell).

## Що саме порівнюється

- **Контрольний варіант:** звичайне масштабування Lanczos3, без відновлення деталей.
- **Real-ESRGAN:** офіційні general x4v3 + weak-denoise ваги, інтерполяція DNI 0.3; виконання через локальний ONNX Runtime на CPU. Збереження моделі, походження, контрольні суми й BSD-3-Clause ліцензія — у `tools/upscale/`. Перекриття тайлів 40px прибирає вплив внутрішніх меж тайлів на результат.
- **Gemini:** той самий оригінальний PNG і промпт на обережний super-resolution без зміни дизайну; запит на 2K і 4:3. Відповіді без достатньої нативної роздільної здатності або з відхиленням пропорцій понад 1% відхиляються як готові результати порівняння, але нативний файл зберігається для перегляду. Допустиме відхилення до 1% зберігається без обрізання чи розтягування: для спільного розміру порівняння додаються тонкі нейтральні поля. Їхні розміри вказуються у звіті; нативний AI-файл без полів доступний окремо. Скрипт не підмінює їх звичайним збільшенням і не обрізає результат, щоб приховати зміну кадру.

Жоден AI-метод не гарантує, що дрібні деталі залишаться точними. Особливо перевірте фурнітуру, малюнок матеріалів, шви, геометрію та ореоли. Звіт не присвоює автоматичну оцінку «якості»: оберіть метод після візуального порівняння.

## Перевірки

`npm run test:upscale` перевіряє запити Gemini на локальних підставних відповідях, відмову від замалих/переформатованих результатів, приховування ключа, підготовку трьох кадрів і пропуск готових генерацій при повторному запуску. Ці тести не звертаються до Google й не витрачають API-квоту.

Real-ESRGAN перевірено окремим реальним запуском на всіх трьох кадрах. Конвертовану ONNX-модель звірено з офіційною мережею PyTorch. Реальні виклики Gemini потрібно перевірити на вашому локальному ПК із вашим ключем; готові відповіді Gemini в цій гілці не заявляються.

## Спробувати 4K

```bash
npm run gallery:compare -- --run --resolution 4k
```

Це **4096 × 3072** для кадру 4:3, а не обрізання до телевізійного 3840 × 2160. Результат потрапляє в нову папку `briller-upscale-comparison-4k-…`; файли мають суфікс `-4k.jpg`. Старе порівняння 1080p залишається окремо. Для `--resume` використовуйте ту саму роздільну здатність, що й у попередньому запуску.

Gemini отримує запит `imageSize: 4K`. Результат 2K не буде просто розтягнутий до 4K й оголошений успішним. Запит 4K може мати іншу вартість/квоту у вашому API-акаунті.

На трьох невеликих кадрах Real-ESRGAN виконує **два нейронні проходи**. Після першого 4×-проходу зайві проміжні пікселі зменшуються приблизно до 1024×768 зі збереженням пропорцій; другий 4×-прохід дає нативний вихід біля 4K. Тонкі поля можуть компенсувати округлення розміру. У звіті збережено фактичні вхідні/вихідні розміри кожного проходу. Це не звичайне розтягування результату першого проходу; водночас другий нейронний прохід теж може змінювати дрібні фактури.

Лише локальний 4K, без Google:

```bash
npm run gallery:compare -- --run --resolution 4k --methods realesrgan
```

## Використати вже отриману відповідь Gemini без повторної оплати

Якщо старий звіт відхилив майже правильні пропорції, наприклад **2400×1792**, оновіть `preview` і виконайте:

```bash
npm run gallery:compare -- --resume --output "/повний/шлях/до/попередньої-папки-порівняння"
```

**Без `--run` скрипт не звертається до API та не виконує нову AI-обробку.** Він перевіряє збережені нативні відповіді, приймає придатні кадри з допуском до 1%, створює JPEG без спотворення пропорцій і оновлює HTML. Ключ Gemini для цього не потрібен. Для відновлення старого 1080p-звіту залишайте стандартну роздільну здатність; для 4K-звіту додайте `--resolution 4k`.

Нативний кадр 2400×1792 достатній для 1080p, але не є 4K. Для справжньої нової генерації 4K потрібен окремий запуск із `--run --resolution 4k`.

Для пакетної обробки всієї галереї лише через Gemini 4K дивіться [окрему інструкцію](GALLERY-GEMINI-4K.md).
