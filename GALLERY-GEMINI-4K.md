# Inspiration Gallery — пакетный апскейл Gemini 4K

Скрипт работает локально. Он не изменяет изображения на сайте, исходную папку, приложение или ветки разработки и ничего не развёртывает.

## Подготовка на Mac

Используйте **отдельную копию репозитория сайта**, а не папку разработки приложения. Если копия для экспорта уже создана:

```bash
cd "$HOME/Downloads/briller-gallery-export-source" &&
git pull --ff-only origin preview &&
npm ci
```

Если её ещё нет, вместо предыдущего блока:

```bash
git clone --single-branch --branch preview https://github.com/brillerhouse/website.git "$HOME/Downloads/briller-gallery-export-source" &&
cd "$HOME/Downloads/briller-gallery-export-source" &&
npm ci
```

Нужен Node.js 20.18+ (как для предыдущего сравнения). Установка Real-ESRGAN и команда `gallery:compare:setup` здесь **не требуются**.

Введите Gemini API key скрытым вводом в том же терминале:

```bash
printf 'Gemini API key: '
read -r -s GEMINI_API_KEY
printf '\n'
export GEMINI_API_KEY
```

Ключ не передаётся в аргументах команд, не сохраняется в файлах, журналах или Git. Он используется в заголовке запроса к Google. Для image-модели нужны доступ, квота и оплата в вашем Google AI Studio / Google Cloud проекте. Не публикуйте ключ в чате.

## Вся текущая галерея: 258 отдельных кадров

```bash
npm run gallery:upscale:gemini -- --run
```

Скрипт берёт **252 варианта дизайна и 6 оригинальных референсов**. Таблицы изображений сначала разделяются по текущим координатам галереи. Для трёх кадров с более качественным `detailImage` используется именно он. В Gemini отправляется исходный кадр без предварительного обычного увеличения до 1080p.

Каталог результатов по умолчанию:

```text
~/Downloads/briller-inspiration-gemini-4k/
```

Для подготовки списка и проверки имён **без запросов к API**:

```bash
npm run gallery:upscale:gemini
```

Это создаёт журнал и отчёт; последующий `--run` использует ту же папку.

При желании сначала обработайте ограниченное число кадров:

```bash
npm run gallery:upscale:gemini -- --run --max-requests 3
```

Затем обычный `--run` продолжит оставшиеся. Ограничение относится к новым запросам в одном запуске, не к размеру каталога.

## Имена и характеристики

Каждый файл из каталога получает имя по схеме:

```text
стиль__тип-помещения__бюджет__размер__площадь-sqm__название__id__ширинаxвысота__4k.jpg
```

Например:

```text
minimalism__living-room__economy__small__13-sqm__minimalism-living-room__living-minimalism-economy__4096x3070__4k.jpg
```

Английские имена совместимы с файловыми системами и поиском. Каталоги разделены по коллекциям и типам помещений. ID предотвращает совпадения имён. Для оригинальных референсов без бюджета, размера или площади используется `budget-unspecified`, `size-unspecified`, `area-unspecified`: скрипт не придумывает отсутствующие характеристики. Тип помещения и стиль берутся из существующего каталога.

`gallery-index.csv` и `gallery-index.json` содержат названия EN/UK, стиль, помещение, бюджет, размер, площадь, архитектурное описание (если задано), коллекцию, исходный ID, размеры, статус и пути к файлам. Длинные архитектурные описания находятся в индексе, чтобы не превысить ограничение длины имени файла. Индекс CSV открывается в Excel / Numbers.

## Своя папка с уже разделёнными изображениями

```bash
npm run gallery:upscale:gemini -- --run \
  --input "$HOME/Downloads/briller-gallery-images" \
  --output "$HOME/Downloads/briller-gallery-images-gemini-4k"
```

Обрабатываются JPG / JPEG / PNG / WebP, включая подпапки. Символические ссылки пропускаются. Структура папок и исходные имена сохраняются, к имени добавляется `__4k.jpg`. Поэтому для полных названий используйте изображения с характеристиками в исходном имени либо стандартный режим каталога выше. Папка результата должна быть вне папки источников; одинаковые имена с разными расширениями выявляются до первого платного запроса.

В этой папке должны быть **отдельные фотографии, а не таблицы из 8 кадров**. Известные исходные таблицы нашей галереи скрипт отклонит с предложением запустить стандартный режим без `--input`.

## Что означает 4K

Модель получает `imageSize: "4K"`. Итоговый холст — **4096 пикселей по длинной стороне**, с пропорциями исходного кадра. Обычно это около 4096 × 3072, квадрат — 4096 × 4096. Округление пикселей при разделении таблицы может дать, например, 4096 × 3070.

Скрипт проверяет разрешение и пропорции нативного ответа. Небольшое отклонение до 1% допускается: изображение вписывается без обрезки и растягивания, при необходимости добавляются тонкие нейтральные поля. Их размеры записываются в журнал. Уменьшение более крупного ответа допустимо; обычное увеличение недостаточного ответа до 4K **не подменяет** успешный AI-апскейл.

Для стандартных пропорций указывается ближайший поддерживаемый Gemini preset с отклонением до 1%. Для нестандартных (например, референса Studio) параметр `aspectRatio` не задаётся: модель просят сохранить исходные пропорции, затем ответ проверяется. Несоответствующий ответ сохраняется для проверки, но не объявляется готовым 4K.

Модель по умолчанию: `gemini-3-pro-image-preview`. Можно выбрать другую **image-модель с поддержкой 4K**:

```bash
npm run gallery:upscale:gemini -- --run \
  --model gemini-3-pro-image-preview \
  --output "$HOME/Downloads/briller-gemini-another-model"
```

Gemini может менять мелкие детали даже при строгом запросе на сохранение сцены. Проверка пикселей и пропорций этого не исключает: просмотрите мебель, геометрию, материалы и мелкие предметы в отчёте перед использованием.

## Результаты и продолжение

- `images/` — отдельные итоговые JPEG 4K с полными именами.
- `inputs/` — точные кадры, отправленные в Gemini.
- `native/` — нативные ответы Google и квитанции с хешем, версией модели и доступными счётчиками токенов; каждая попытка хранится отдельно.
- `job.json` — контрольные точки и состояние обработки.
- `gallery-index.csv`, `gallery-index.json` — характеристики и статусы.
- `report.html` — локальный отчёт с поиском, фильтром статусов, оригиналами, результатами и ссылками на нативные ответы.

Открыть отчёт на Mac:

```bash
open "$HOME/Downloads/briller-inspiration-gemini-4k/report.html"
```

Для продолжения после закрытия терминала или Ctrl+C выполните ту же команду с тем же `--output`. При новом терминале снова задайте ключ. Проверенные готовые файлы пропускаются. Сохранённый нативный ответ можно восстановить без ключа и без API, в том числе если выполнение оборвалось до создания итогового JPEG. Смена источников, имён, промпта или модели требует новой папки результатов; существующая работа сохраняется. Не запускайте одновременно две копии с одной папкой результатов — блокировка предотвращает это.

Каждый новый запрос может оплачиваться Google; полный каталог предполагает до 258 первичных запросов, повторные попытки оплачиваются отдельно. Автоматических повторов платной генерации нет. При 429, ошибке доступа, сетевом сбое или таймауте запуск останавливается. После трёх подряд непригодных ответов по разрешению/пропорциям обработка также останавливается, чтобы можно было проверить модель и настройки.

Статусы:

| Статус | Значение |
|---|---|
| `pending` | Запрос ещё не отправлен |
| `requesting` | Запрос начат; контрольная точка сохранена |
| `received` | Нативный ответ надёжно сохранён |
| `complete` | Итоговый JPEG прошёл проверку размера и пропорций |
| `needs_review` | Ответ требует проверки; нативное изображение сохранено, если оно было получено |
| `error` | API вернул ошибку, например отсутствие квоты |
| `uncertain` | Неизвестно, завершился ли запрос у Google; списание возможно |

Обычный повторный запуск продолжит `pending`, но **не повторит** `error`, `uncertain` или `needs_review`. После проверки отчёта и исправления причины можно явно разрешить новые попытки:

```bash
npm run gallery:upscale:gemini -- --run --retry-failed
```

При таймауте невозможно гарантировать отсутствие оплаты первого запроса, даже если изображение не пришло. `--retry-failed` означает осознанное разрешение новой попытки. Сохранённые корректные ответы всё равно используются без повторной генерации.

Если после просмотра нативного ответа вы согласны на отклонение пропорций до 3%, можно повторно проверить сохранённые ответы **без API**:

```bash
npm run gallery:upscale:gemini -- --aspect-tolerance 0.03
```

Это не растягивает и не обрезает изображения; допускает больше нейтрального поля. Максимальное значение — 0.05. Низкое разрешение таким способом не принимается.

Пауза между запросами по умолчанию 2000 мс, изменяется через `--delay-ms`. Общая длительность зависит от модели и квоты; нативные ответы и 4K JPEG всего каталога могут занять несколько гигабайт.

## Проверки реализации

```bash
npm run test:upscale
```

Тесты используют искусственные изображения и имитацию API: проверяют 4K-запросы, имена, разрезание галереи, продолжение, восстановление, ограничения числа запросов, ошибки, блокировку и отсутствие ключа в журнале. Они не подтверждают доступность модели или визуальное качество реальной генерации в вашем аккаунте Google.
