# Окремі фото Gemini 4K замість кластерів у галереї

Імпортер підключає **готові результати**, отримані через `gallery:upscale:gemini`. Він не генерує зображення і не робить запитів до API. Потрібна вся папка `briller-inspiration-gemini-4k`, зокрема `job.json` та `images/`.

## Локальна підготовка

У копії репозиторію **сайту**, де ви запускаєте експорт/апскейл:

```bash
cd "$HOME/Downloads/briller-gallery-export-source" &&
git pull --ff-only origin preview &&
npm ci
```

Якщо папка Gemini має стандартну назву, перевірте її:

```bash
npm run gallery:import:4k
```

Або вкажіть іншу папку:

```bash
npm run gallery:import:4k -- --input "/шлях/до/briller-inspiration-gemini-4k"
```

До будь-якого запису перевіряються:

- Повний набір із 252 дизайнів і 6 референсів; кожен має статус `complete`.
- Відсутність повторних або загублених ID.
- Відповідність вихідному зображенню і кадруванню в поточному каталозі.
- SHA-256 кожного готового файла, справжній формат, роздільність 4096 пікселів по довгій стороні та збереження пропорцій.
- Відсутність однакових результатів і шляхів за межі папки імпорту.

Незавершений апскейл, результати порівняння трьох кадрів та звичайний експорт 1080p не приймаються як готовий набір 4K.

## Підключення до локального сайту

```bash
npm run gallery:import:4k -- --apply
BRILLER_PREVIEW=1 npm run dev -- --port 3001
```

Для нестандартного розташування папки додайте `--input "/ваш/шлях"` до команди імпорту.

Відкрийте <http://localhost:3001/en/gallery/> або <http://localhost:3001/uk/gallery/>.

Імпортер створює окремі WebP для кожного фото: шириною 640, 1280, 2048 і 4096 пікселів. `srcset` дозволяє браузеру вибирати розмір для екрана; повна 4K-версія доступна для великого перегляду. Назви містять стиль, приміщення, бюджет, розмір, площу, назву, ID і роздільність. Невідомі характеристики референсів не вигадуються.

Усі файли нового набору спочатку готуються окремо. Лише після завершення вмикається єдиний маніфест `content/gallery-web-images.json`. Картки, великий перегляд, метадані SEO, експорт і перевірка якості використовують однакове відображення ID → окреме фото. Старі кластери залишаються у репозиторії як джерела й історія; після підключення набір галереї їх не завантажує. Існуючі назви, фільтри, ID та промпти зберігаються.

Повторний імпорт тих самих файлів перевіряє існуючий набір, а не перезаписує його. Різні набори мають різні адреси файлів, тому браузер не показуватиме старе кешоване фото за новим посиланням.

## Перевірка перед публікацією

Gemini міг змінити деталі. Імпорт **не переписує візуальні схвалення** попередніх фото:

```bash
npm run gallery:review
```

Це підготує `.gallery-review/index.html`, аналіз і нові записи `pending-reviews.json`. Перегляньте нові фото та порівняння подібних кадрів за існуючим процесом у `content/gallery-README.md`. Нові байти потребують нових фактичних спостережень у `content/gallery-quality-review.json`; старі схвалення не поширюються автоматично на AI-апскейл.

Після візуальної перевірки:

```bash
BRILLER_PREVIEW=1 npm run build &&
npm run check &&
BRILLER_PREVIEW=1 npm test
```

Змінені файли для Git: `content/gallery-web-images.json`, фактичні оновлені записи якості та `public/images/gallery/individual/<набір>/`. Вихідний `job.json`, ключ Gemini, PNG/JPEG із папки апскейлу і тимчасові файли до репозиторію не додаються.

Імпорт і локальний сервер не оновлюють briller.house: публікація відбувається окремим процесом розгортання сайту після перевірки готового набору.
